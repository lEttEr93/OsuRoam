# 本地开发与快速启动

## 最省事的三种开法

| 想要 | 怎么做 |
|---|---|
| **双击图标开** | 先跑一次 `create-shortcut.cmd`（我没权限往你的桌面写），之后桌面上就有「osu! Roam (dev)」，双击即可 |
| **任意 cmd 里开** | `roam`（`D:\AI\bin\roam.cmd` 转发，已在 PATH 里） |
| **改了代码自动重开** | `roam-watch` 或仓库里的 `watch.cmd`，保存 `.cs`/`.xaml` 就重启 |

三者背后都是 `run.cmd`：**有改动就增量编译（没改动约 2 秒）→ 关掉旧实例 → 启动新实例**。
不闪黑框（桌面快捷方式走 `roam.vbs`），编译失败会直接打开 `bin\run-build.log`。

再双击一次 = 重开一个新实例（这样才能应用刚改的代码）。而**直接双击 exe**（`bin\Debug\net8.0-windows\OsuRoam.exe`）
碰到已在运行的实例时，不会再弹「已经有一个在运行了」，而是把那个窗口叫到前面后自己退出。

数据固定在 `bin\Debug\net8.0-windows\data`（便携模式）：配置、键型库、谱面缓存跨次启动都留着，
第一次填的 tosu 路径 / OAuth 凭据之后不用重复填。

脚本会替你处理三件容易踩的事：

- **重开前先关掉旧的 Debug 实例** —— 否则编译覆盖不了正在运行的 exe（只按路径认
  `bin\Debug\net8.0-windows\OsuRoam.exe`，不会误杀发布版）；
- **把 tosu.exe 硬链接到 `bin\Debug\net8.0-windows\`** —— Roam 优先用自己目录下的 tosu，
  这样开发版不依赖设置里那条可能早就不存在的旧路径（硬链接，瞬间、不占额外空间）；
- **TMP/TEMP 指到 `bin\tmp`** —— 见下面「临时目录」。

`run.cmd` 里有两个 cmd.exe 的坑，注释里写了，别「简化」掉：

- 批处理的位置参数 `%1..%9` 会在 `=` 和 `;` 上切分 —— `--preview=fps` 会变成 `--preview` + `fps`
  两个参数，所以脚本用 `%*` 拿原始参数串；
- `start` 自己也会在 `=` 上切分它收到的命令行，所以参数必须保持带引号。

（`run.cmd` / `watch.cmd` 因此必须保持纯 ASCII：cmd.exe 按 OEM 代码页读 `.cmd`，
UTF-8 中文会把引号吃掉，整行语法就废了。）

## 保存即重启

```
watch.cmd               # 编译 + 启动，之后每次保存 .cs / .xaml 自动重开
watch.cmd --preview     # 参数原样传给程序
```

- 只盯源码（根目录的 `*.cs` / `*.xaml` / `*.csproj` + `Controls` / `Models` / `Services` / `Properties`），
  `bin` / `obj` / `data` 里的变化不算 —— 否则编译产物会把自己再触发一次。
- 顺序是「先停旧进程 → 编译 → 启动」，所以编译时不会撞上 exe 被占用。
- 编译失败只打错误行，不重启，等下一次保存。
- 强制结束的实例不会顺手关掉它启动的 tosu，需要的话自己结束一下。
- 实测：没改动时重启约 2 秒（增量编译几乎不花时间），改一个 `.cs` 约 10 秒
  （WPF 项目要重建 XAML 那一套）。

`pwsh` 在就用 7，没有就退回 Windows PowerShell 5.1（`watch.ps1` 严格转 UTF-8 BOM，
5.1 才不会把中文当 ANSI 读）。

启动子进程用的是 `ProcessStartInfo` + `UseShellExecute=$false`（普通 CreateProcess），
不是 `Start-Process` —— 后者走 ShellExecute，在部分宿主里会卡住不返回。

## 临时目录（这台机器必须处理）

`TMP` / `TEMP` 指向 `C:\Users\<用户>\AppData\Local\Temp`，而这台机器上 MSBuild 写不进去
（ACL 拒绝），报出来只有一句 `MSB1025：运行 MSBuild 时发生内部错误`，没有任何线索。
两个脚本都把 `TMP` / `TEMP` 改成仓库内的 `bin\tmp` 再编译。

## dotnet 路径

这台机器 `PATH` 上的 `C:\Program Files\dotnet\dotnet` **没有装 SDK**，直接 `dotnet build`
会报 "SDK not found"。两个脚本都按这个顺序挑：

1. `%DOTNET_ROOT%\dotnet.exe`（有定义时）
2. `D:\AI\tools\dotnet\dotnet.exe`（8.0.425）
3. `PATH` 上的 `dotnet`

## 开发参数

| 参数 | 作用 |
|---|---|
| `--snapshot=<png>` | 截图后退出；可配 `--with-info` / `--mini-idle` / `--pending` / `--notice[=memory\|nobeatmap]` / `--expand` / `--empty` / `--scroll=0..1` |
| `--rangetab=basic\|tag\|pattern` | 截图前把「推荐范围」切到指定标签页（切完会把窗口/内容/标签条宽度和可滚高度写进日志） |
| `--mode=osu\|taiko\|fruits\|mania` | 截图前走一遍真正的模式按钮点击（含反馈动画）；**会改掉 data\settings.json 里的模式和星级区间**，测完记得还原 |
| `--anim-delay=<ms>` | 切换后等多久再截图，默认 300；调小到 40–90 能拍到动画中途那一帧 |
| `--tooltip-probe` | 手动开一个提示气泡，验证 TopmostKeeper 会让路（日志里看浮层计数 0→1→0） |
| `--section=range\|account\|interface\|advanced` | 截图前把底部标签条的那一块展开（`--update-ui` 时会把它滚到底） |
| `--update-check` | 查一次更新、把结果写进日志后退出（不弹窗、不改文件） |
| `--update-auto-test` | 把「启动后自动检查更新」的 20 秒压成 2 秒，跑完自己退出（验自动检查那条链路） |
| `--update-ui` | 截图前跑一次真的检查更新，拍「已是最新 / 发现新版本」那一行 |
| `--pool-probe` | 用真实账号跑一遍「搜索 → 候选补给 → 排池」，再模拟连点 4 次「下一首」，把每一层数字（总池 / 已判 / 达标 / 未消费达标 / 补位）和「刚移出的会不会被补回来」写进日志后退出。不进 osu!、不导入谱面；测前建议把 `AutoDownload` 置 false |
| `--snapshot-ln` | 截图时把信息窗那张谱改成面谱（LN 36%），用来核对 LN 三角的形状与绘制动画 |
| `--preview[=noclock\|layered\|fps\|fps-layered\|fps-tiny\|fps-static]` | 预览窗截图 / 帧率探针（见 `1.5.5-谱面预览.md`） |
| `--experiment[=profile\|ingame\|library\|bpm]` | 跑完实验、写报告后退出 |
| `--diag` | 跑启动诊断后退出 |

## 排查：tosu 起不来

日志里出现 `tosu stderr: Error: EPERM … mkdir 'C:\Users\<用户>\.cache\pkg\…'` 时，
看 `docs/tosu-启动失败.md` —— 那是 pkg 解原生模块被用户目录权限挡住，
Roam 现在会把 tosu 的用户目录改到 `data\tosu-home` 绕开它。
