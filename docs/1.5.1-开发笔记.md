# 1.5.1 开发笔记

## 已修：导入下一首要等新谱面下载完（计划里的「计划修复 1」）

症状：池里 5 张都预下载好了，但触发「导入下一首」时，要等后面新加入的那张下完才动。

根因在两处串行化：

1. `BeatmapDownloadService.DownloadAsync` 一开始就 `await queue.WaitAsync()`，
   **即使文件已经在缓存里**也要排在预下载后面；
2. `ImportAsync` 用的是**同一把** `queue`，所以导入本身也被一次几个 MB 的下载挡住。

改法：

- `DownloadAsync` 先查文件（存在且 ≥1024 字节）→ 直接返回，不进队列；
- `ImportAsync` 换成独立的 `importGate`，只串行化「校验 + `Process.Start`」，
  不再和下载抢；
- `MainWindow.downloadItemAsync` 把「确保下载」和「确保解析」拆开：
  已 `Downloaded` 的不再调下载，只在 `Detail`/`Pattern` 缺失时补解析
  （重启后缓存还在但没解析过的情况也能覆盖）。

## 待做：更好的去重（计划里的「计划新增 1」）

调研结论（tosu v4.26.1，源码 `packages/server/router/v1.ts`）：

- `GET /Songs/{path}` 会遍历 osu! 的 Songs 目录；`GET /Songs/` 返回 **HTML 目录列表**
  （`<li><a href="...">文件夹名</a></li>`），不是 JSON。
- 必须有 osu! 在运行：否则 500 `{"error":"osu is not ready/running"}`。
- osu!stable 的目录名是 `<setId> <artist> - <title>`，所以**一次请求**就能拿到整个
  已安装曲库的 set id；要拿「哪些难度已装」得逐目录再请求一次。

由此定下的方案：

1. 启动/定期 `GET /Songs/`，解析出已安装的 setId 集合（一次请求，缓存几分钟）；
2. 排除逻辑从「按 set 排除」改成「按难度排除」——准备收录某个 set 时，
   再 `GET /Songs/{该 set 的目录}/` 拿到里面的 `.osu` 文件名（难度名在文件名里），
   只排除**已装的那个难度**，同曲的其他难度照常推荐；
3. tosu 没开或 osu! 没开时静默退回现在的行为（历史 + 最近成绩）。
